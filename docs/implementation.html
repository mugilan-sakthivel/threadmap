ThreadMap MVP: implementation doc

26 Oct 2026 · repo threadmap/ · branch feat/live-mvp (local, not pushed)
Built: a working Next.js app. You talk, the transcript and notes log on the right, and the canvas draws the conversation live: questions become sections, and spoken structures (pyramid, “4 methods”, steps, cycle, X vs Y, timeline) become real diagrams that fill in slot by slot. Sections flow top to bottom, then into a new column on the right, and the camera follows the active section.

1. What was built

  • Setup screen (Flowjam-style): title, spoken language (Tamil/Hindi/Telugu/Malayalam/Kannada + English, English), map language (English / தமிழ் / हिन्दी / same as spoken), audio source, names to spell right. Shows which keys are configured.
  • Live screen: Excalidraw canvas with a floating dark dock (timer, pause, follow live), right panel with ① live transcript (speaker names, timestamps, grey live partial, click a name to rename) and ② notes (open follow-ups pinned at top in the black “selected” style, tap when asked, plus points, quotes and clip ideas).
  • Speech engines: Soniox real-time (mic, or mic + a shared call tab for the remote guest), free browser speech (Chrome), and a scripted Tanglish demo that needs no keys.
  • AI brain: any OpenAI-compatible model returns {notes, ops} JSON. Validated per item with zod, so bad items are dropped and never crash the board.
  • Diagram engine: 8 deterministic templates, column-flow layout, stable element ids, Indic-aware text wrapping.
  • After the session: the canvas unlocks for manual editing, plus “Download PNG” and “Fit all”.

2. Keys you need to give (in threadmap/.env.local, never in chat)

KeyWhat it enablesWithout it
SONIOX_API_KEYReal-time mic transcription with speaker labels and Tamil/Hindi + English mixing (~$0.12/hr)Use “Browser speech (free)” in Chrome, or the demo
LLM_BASE_URL + LLM_API_KEY + LLM_MODELThe AI that draws diagrams and writes notes from your speechOnly the demo draws (from pre-recorded steps). Live speech is transcribed but not drawn

Any OpenAI-compatible provider works: OpenAI, Gemini (OpenAI endpoint), Groq, OpenRouter, OpenCode Zen. Examples are in .env.example. Pick a fast, cheap model with reliable JSON (e.g. gemini-2.5-flash, gpt-5-mini). If your provider rejects JSON mode, set LLM_JSON_MODE=off.

3. How it works

mic ─▶ Soniox WebSocket (browser, 60s temp key from /api/stt-token)
     ─▶ TokenAssembler: word pieces → speaker segments (split on endpoint / speaker change)
     ─▶ transcript log
     ─▶ BrainScheduler: debounce 1.5s, max wait 6s, one call in flight, retry w/ backoff
     ─▶ POST /api/brain → LLM → {notes, ops} → zod (drop bad items)
     ─▶ reducer(board, ops) → layoutBoard (column flow) → templates → shapes
     ─▶ Excalidraw elements (stable ids, centered text) → updateScene + follow camera

Why “how do we show a pyramid?” works: the prompt teaches the model to spot visual cues (“pyramid / layers / foundation”, “there are N ways”, “first… then”, “it repeats”, “X vs Y”, dates). It only names the template and fills slots. Code draws the shape, so “there are 4 methods” instantly shows 4 dashed boxes that turn solid (pink while being drawn) as each is explained.

5. Decisions and tradeoffs

  • AI outputs meaning, code does geometry. Clean, stable diagrams and cheap models, at the cost of a fixed template set (8 shapes) rather than free-form drawing.
  • Browser streams straight to Soniox with a 60s temporary key. Lower latency and no audio relay server. The permanent key never reaches the client.
  • Any OpenAI-compatible LLM via one client and a base URL, so switching provider is a config change.
  • Canvas is AI-owned while live (view mode) and becomes editable when the session ends. Live manual edits would otherwise be overwritten by the next AI update.
  • Layout reflow: earlier sections stay fixed as new ones are added (tested). If the AI later adds to an old section, sections after it can shift. That's acceptable and rare.
  • Fonts: Fraunces + Hanken Grotesk (free look-alikes of Flowjam's paid fonts). Excalifont on the canvas, with Tamil/Hindi falling back to system fonts (verified rendering).

7. How it was tested

  • 51 unit tests pass (vitest): reducer, layout (column flow, no overlaps, earlier sections stable, unique ids), all 8 templates, overlap checks at 12 slots, cycle overflow, schema parsing, scheduler (debounce, max wait, disable, retry, flush), token assembler, Tamil/Hindi wrapping.
  • typecheck, lint, production build pass.
  • Live browser test, demo (no keys): pyramid → 2×2 grid → steps → comparison, with section 4 flowing into column 2. Notes, follow-up pinned then resolved, auto-end, pause/resume timer, end, new session.
  • AI path with a local mock OpenAI-compatible server: JSON mode sent, auth header sent, invalid op dropped, prose-wrapped JSON parsed, visuals grow live. AI-down mid-session shows “AI error” and the transcript continues. Tamil + Hindi labels render on the canvas.
  • Route guards: cross-site 403, oversize 413, missing key 503, invalid body 400.
  • Not yet tested: real Soniox streaming and a real LLM (no keys here), and mic + tab-audio capture on a real call.

8. Independent review

Codex (gpt-5.x) could not run: this ChatGPT account rejects every Codex model. An independent Claude reviewer was used instead. See the section below for its findings and what was fixed.

FindingFix
Soniox never reconnected after a network drop (SDK default off)auto_reconnect: true, 6 attempts. Final words kept on reset
Mic+tab source corrupted WebM on pause/reconnectReal MediaRecorder.pause/resume + restart() with a fresh recorder
Browser speech looped forever on fatal errorsFatal error codes stop the auto-restart
Transcript could be skipped after a long AI stallRequest window starts at the oldest unsent segment, capped at 80 (tested)
Whole board re-sketched (wobbled) on every updateDeterministic rough.js seed per element id (tested)
Pause ignored while still connectingPause enabled only once the engine is live
Ending could hang on a stalled socket5s timeout, then cancel

Also added after review: the prompt now handles unannounced lists (“effective, efficient, honest”), steps, contrasts and cycles that aren't named, and the demo includes that case.

9. Confidence

~85% that the MVP is correct and complete for its scope. The board, layout, templates, scheduler and UI flows are verified by tests and a live browser run. The remaining risk is in the parts I couldn't run here: real Soniox streaming (SDK event ordering, mixed-language accuracy) and real LLM quality (how well a given model picks the right template). Both need a 10-minute test with your keys, which is the next step.
