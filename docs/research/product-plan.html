Live conversation map for podcast hosts

Product plan · 25 Oct 2026 · working name: “ThreadMap” (placeholder)

1. Is it useful? Yes, and here's why

The reframe makes the idea stronger. Hosts already take notes mid-interview: they jot follow-ups, track which questions they've covered, and use those notes to write the summary later. This product replaces the notepad. The host sees a live map of what I asked → how the guest answered → what's still open, and the summary writes itself from that map afterward.
  • Hosts are already looking at notes. This doesn't add a new screen. It swaps a messy notepad for a glanceable map, the way a teleprompter is used.
  • None of the incumbents do this live. Riverside, Castmagic, and Descript only work after recording. Otter is live but shows plain text, with no question→answer structure.
  • One session gives you two outputs: the live map (during the show) plus the summary, show notes, chapters, and a shareable visual (after).
  • The design rule that makes it work: the screen must be readable in 1 second, with big text and calm motion, and it must never demand attention. If the host has to read it, it has failed.

3. Multi-language: your real wedge

Western tools are built English-first. Indian podcasters constantly code-switch (Hinglish, Tanglish), and that's where Riverside and Castmagic are weak. India is cited as the #3 podcast market, with Hindi plus regional shows growing fastest. Start with English + Hinglish + Tanglish and you have a niche the big players aren't serving.

EngineUse forNotes

Rule: the language model (LLM) always reads the original transcript and writes labels in the chosen map language. Don't translate the transcript first, because you lose nuance and add latency. Romanized vs native script (தமிழ் vs “Tamil in English letters”) is a per-user toggle.

4. Architecture

🎙 Host mic + guest audio
(2 tracks ideal) → STT adapter
Sarvam / Deepgram / AssemblyAI → Transcript buffer
speaker-tagged → Conversation engine
fast LLM → semantic ops → Graph state
questions, points, threads → Layout engine
deterministic, incremental → Excalidraw canvas

Key design decisions

  1. The LLM outputs meaning, never coordinates. It returns ops like add_question, add_point(q_id), open_thread, close_thread, tick_prep(item). A deterministic layout (tree via dagre/ELK) places things. That keeps the canvas from jumping around when the LLM rephrases.
  2. Append-only, stable layout. Existing nodes never move, and new ones attach below. Old questions collapse after about 20 min so a 2-hour show stays readable.
  3. Draft → commit. While the guest talks, show a faded “draft” node. Commit it when the speaker pauses (end-of-utterance from STT). That gives a responsive feel without flicker.
  4. Host vs guest identification: best is 2 separate audio tracks (host mic plus system/guest audio). Fallback is diarization plus a “say hi, host” calibration in the first 10 seconds.
  5. Two LLM tiers: a fast, cheap model for live ops (every utterance, under 1–2s) and a strong model once at the end for the summary pack, reading the full transcript plus graph.
  6. MCP is for dev, not runtime. Use the Excalidraw MCP to prototype layouts inside Claude. The product uses the @excalidraw/excalidraw React component directly.

Suggested stack

Next.js + TypeScript web app (desktop-first, works on a laptop next to the mic) · WebSocket relay server (Node) holding provider keys · Postgres for sessions/graphs · object storage for audio (optional, opt-in) · Excalidraw React component · audio via browser getUserMedia. Riverside/Zoom users route guest audio through a virtual device (BlackHole/VB-Cable) or use tab-audio capture.

8. Validation before building beyond the spike

  1. Build Phase 0 and run it on 3 public episodes: one English, one Hindi-English, one Tamil-English.
  2. Record a 60-second screen capture of the map building itself live. That's your pitch.
  3. Send it to 30 podcast hosts (Tamil/Hindi tech, startup, and interview shows first) and ask: “Would you use this on your next recording?” Then book 10 for a live test.
  4. Landing page with ₹399/$9 founding-member pre-order.
  5. Go if ≥3 of 5 testers reuse it on a second episode, or ≥20 pre-orders. Otherwise keep it as a portfolio piece.
